# TuneBridge

Локальное веб-приложение для переноса плейлистов между музыкальными сервисами: Яндекс Музыка, Spotify, YouTube Music, SoundCloud и Apple Music → Spotify / YouTube Music / файлы. Публичные плейлисты открываются по ссылке без входа. Работает на вашем компьютере, без облака и регистрации в сторонних сервисах.

Тот же код работает публичным сервисом — Telegram Mini App с входом через Telegram, личным кабинетом и собственной рекламой. По умолчанию сервис бесплатный: без токенов, списаний и пополнений. Экономика токенов осталась как опция и включается одной переменной окружения.

## Возможности

- **Источники:** Яндекс Музыка, Spotify, YouTube Music, SoundCloud, Apple Music, файлы M3U/M3U8/CSV/JSON/TXT, демо-плейлист.
- **Публичный импорт без входа:** ссылки Spotify, YouTube Music, SoundCloud и Apple Music открываются сразу — аккаунт нужен только для своих плейлистов и сохранения.
- **Цели:** Spotify, YouTube Music, экспорт файлов.
- **Сопоставление треков** по названию, исполнителю и длительности с автоматическим порогом, ручным подтверждением и поиском замены.
- **Перенос** с прогрессом в реальном времени, отменой, повторами при ошибках и докаткой батчами.
- **Экспорт** в ZIP: M3U8, CSV, JSON и README.
- **Отправка в Telegram** через своего бота: список треков со ссылками и ZIP-архив плейлиста в личный чат, группу или канал.
- **Личный кабинет:** история переносов и подключения. В платном режиме — кошелёк, заказы, промокоды и админ-панель.
- **Бесплатный режим:** переносы без токенов и лимитов; доход — собственный рекламный блок на главной и в результате.
- **Публичный хостинг:** Docker + Caddy с автоматическим HTTPS, деплой из GitHub Actions на Oracle Always Free, PWA и Android TWA.
- **Telegram Mini App:** вход по подписи Telegram, сессии в cookie, данные аккаунта на сервере.
- **История переносов** и настройки — в аккаунте (в локальном режиме — в браузере).
- **Русский и английский интерфейс** — переключатель RU/EN в шапке, выбор запоминается; язык определяется автоматически по языку браузера.
- Адаптивная вёрстка для телефона и десктопа.
- **С телефона по Wi-Fi:** QR-код с адресом, установка иконки на главный экран (PWA).

## Быстрый старт

Нужен Python 3.11 или новее.

**Windows:** дважды щёлкните `start.bat`. Скрипт создаст `.venv`, установит зависимости и откроет <http://127.0.0.1:8787>.

**macOS / Linux:**

```sh
chmod +x start.sh
./start.sh
```

**Вручную (Windows):**

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

**Вручную (macOS / Linux):**

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

Браузер откроется автоматически. Чтобы не открывать его: `TUNEBRIDGE_OPEN_BROWSER=0`.

### Демо за минуту

На главной выберите **Демо** → **Загрузить плейлист** → цель **Демо-плеер** → **Сопоставить** → проверьте спорные совпадения → **Перенести**. Аккаунты не нужны.

## Подключение сервисов

### Яндекс Музыка

- **Публичный плейлист** — просто вставьте ссылку вида `music.yandex.ru/playlists/…` или `music.yandex.ru/users/<логин>/playlists/<id>`. Вход не требуется.
- **Свои плейлисты** — в боковой панели нажмите «Подключить» у Яндекса: приложение покажет код, его нужно ввести на <https://ya.ru/device>. Код действует около 5 минут. Можно вставить OAuth-токен вручную.
- Используется неофициальная библиотека `yandex-music`, поэтому доступ может измениться со стороны сервиса.

### Spotify

- **Публичный плейлист** — вставьте ссылку `open.spotify.com/playlist/…`: TuneBridge прочитает страницу без входа. Если у плейлиста больше 100 треков, приложение предупредит — полный список доступен только с аккаунтом.
- **Свои плейлисты и сохранение** — нужно один раз подключить аккаунт:
  1. Создайте приложение на <https://developer.spotify.com/dashboard/create> (или в <https://developer.spotify.com/dashboard>).
  2. В настройках приложения добавьте Redirect URI **точно**:
     `http://127.0.0.1:8787/api/auth/spotify/callback`
  3. Скопируйте **Client ID** и вставьте его в окне подключения TuneBridge — откроется страница входа Spotify.

Используется OAuth PKCE, Client Secret не нужен. В режиме разработки Spotify приложение доступно только аккаунтам, добавленным в Dashboard (до 25 пользователей).

### YouTube Music

- **Публичный плейлист** — вставьте ссылку `music.youtube.com/playlist?list=…`: он откроется без входа.
- **Свои плейлисты и сохранение — в одно нажатие:**
  1. Войдите в YouTube в обычном браузере на этом компьютере.
  2. В окне подключения TuneBridge нажмите **«Подключить из браузера»**.

  Приложение само найдёт cookie YouTube в профилях Яндекс Браузера, Chrome, Edge, Opera или Firefox **на компьютере, где запущен TuneBridge**, и проверит вход. Cookie не покидают компьютер и никуда не отправляются. Если в браузере несколько аккаунтов Google, TuneBridge покажет их список и подключит выбранный — первый по списку больше не подставляется молча.

  Кнопка **«Подключить из браузера»** работает только на самом компьютере с TuneBridge. С телефона по Wi-Fi и в хостинге её нет: там приложение не должно читать чужие браузеры. В этих случаях cookie вставляется вручную: `F12` → **Network** → обновите страницу → запрос с `youtubei` → **Headers → Request Headers** → строка `cookie` → **Copy value**. Для Mini App cookie нужно скопировать в браузере на компьютере, где выполнен вход в нужный аккаунт.

Подпись запроса (SAPISIDHASH) TuneBridge считает сама и обновляет при каждом обращении, поэтому вход не «протухает» через час. Cookie даёт полный доступ к аккаунту — не передавайте его никому. Это неофициальный способ доступа.

### SoundCloud

Вставьте ссылку на сет: `soundcloud.com/<автор>/sets/<название>`. Аккаунт не нужен, ссылки `on.soundcloud.com/…` тоже поддерживаются. Скрытые и приватные сеты без входа недоступны.

### Apple Music

Вставьте публичную ссылку `music.apple.com/…/playlist/…` (или `itunes.apple.com/…/playlist/…`). Аккаунт не нужен. Страница Apple отдаёт до 100 треков за раз — если в плейлисте больше, приложение покажет предупреждение.

### Telegram

Плейлист можно отправить в Telegram через собственного бота — без сторонних сервисов.

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и получите токен вида `123456789:AAH…`.
2. В окне «С ботом» на главной или в результате переноса вставьте токен и нажмите **«Подключить бота»**.
3. Откройте бота в Telegram и нажмите **Start**. Куда отправлять: пустое поле — чат с ботом, `@username` — канал или группа (бот должен быть там администратором). Кнопка **«Найти чаты»** подскажет доступные.

Что уходит: список треков со ссылками на исходный сервис и, по желанию, **ZIP-архив** плейлиста (M3U8, CSV, JSON). Длинный список разбивается на несколько сообщений; если треков больше 150, в сообщении остаются первые 150, а полный список — в архиве и в файлах.

> **Аудиофайлы TuneBridge не скачивает.** Музыкальные сервисы не отдают треки официально, а обход защиты — нарушение их условий. В Telegram уходят список и архив плейлиста, а не музыка. Честно показываем это и в интерфейсе.

Токен — это полный доступ к боту. Он хранится локально в `data/telegram.json`, никуда не отправляется; «Отключить бота» удаляет файл.

## Хостинг, Mini App и оплата

Хостинг включается сам, как только задан `TUNEBRIDGE_BOT_TOKEN`. Без токена приложение работает как раньше — локально, без входа, с тестовым пополнением.

### Что нужно на сервере

1. Домен и HTTPS: Telegram открывает Mini App только по `https://`.
2. Переменные окружения:

   ```sh
   TUNEBRIDGE_HOST=0.0.0.0
   TUNEBRIDGE_BASE_URL=https://tunebridge.example.com
   TUNEBRIDGE_BOT_TOKEN=123456789:AAH…
   TUNEBRIDGE_BOT_USERNAME=tunebridge_bot
   TUNEBRIDGE_WEBHOOK_SECRET=<случайная строка>
   TUNEBRIDGE_SECRET_KEY=<длинная случайная строка>   # ключ шифрования подключений пользователей
   TUNEBRIDGE_ADMIN_IDS=123456789          # ваш Telegram ID, можно несколько через запятую
   TUNEBRIDGE_COOKIE_SECURE=1
   ```

   `TUNEBRIDGE_SECRET_KEY` шифрует токены и cookie пользователей в базе. Если он не задан, ключ выводится из токена бота: приложение работает, но смена токена сделает сохранённые подключения нечитаемыми. Для публичного сервиса задайте отдельный ключ и храните его в секрете (менеджер секретов, не в git).

3. База: рядом с приложением появится `data/tunebridge.db` (SQLite, WAL). Для нескольких инстансов или больших нагрузок слой `app/db.py` переносится на PostgreSQL — схема и запросы обычные, PostgreSQL-драйвер пока не подключён.
4. Бэкапы: копируйте `data/tunebridge.db` (и `-wal`, `-shm`) либо делайте `sqlite3 tunebridge.db ".backup backup.db"` по расписанию.
5. Мини-приложение в BotFather: `/newapp` → выберите бота → укажите название, описание, картинку и URL `https://tunebridge.example.com/`. Кнопка меню бота тоже может открывать этот адрес.

### Вход

- Приложение получает `initData` от Telegram, проверяет HMAC-SHA256 (ключ — `WebAppData` + токен бота), свежесть `auth_date` (по умолчанию сутки) и только затем создаёт пользователя и сессию.
- Сессия — случайный токен в HttpOnly-cookie `tb_session`; в базе хранится только его SHA-256. Срок — 30 дней (`TUNEBRIDGE_SESSION_TTL`).
- Небезопасные запросы требуют заголовок `X-TB-CSRF` из `/api/session`. Cookie и `initData` никогда не пишутся в логи.
- Админы задаются через `TUNEBRIDGE_ADMIN_IDS`; им доступны начисления, промокоды и возвраты в кабинете.

### Подключения сервисов в аккаунте

- В хостинге токены Яндекс Музыки, Client ID и OAuth-токен Spotify, cookie YouTube Music, состояние входа по коду и выбранный чат Telegram хранятся в базе **отдельно для каждого пользователя** и шифруются Fernet (AES + HMAC) ключом `TUNEBRIDGE_SECRET_KEY`.
- Запросы Mini App и фоновые задачи выполняются в контексте конкретного аккаунта, поэтому чужие подключения недоступны. Кеши клиентов Spotify и YouTube Music тоже разделены по пользователю.
- Наружу уходят только имя профиля, маска Client ID и признак «подключено»; токены и cookie не попадают ни в ответы API, ни в логи.
- Отключение сервиса удаляет запись из базы. Смена ключа шифрования делает старые записи нечитаемыми — подключения придётся повторить.
- Отправка в Telegram в хостинге идёт от общего бота TuneBridge: список чатов бота не показывается (он общий для всех), по умолчанию выбирается личный чат пользователя.
- Интерфейс в хостинге не показывает «С телефона по Wi-Fi», а подсказки про `data/` заменяет на хранение в аккаунте пользователя.
- В локальном режиме всё как раньше: файлы в `data/` без шифрования.

### Бесплатный и платный режимы

Для публичного запуска включён **бесплатный режим** (`TUNEBRIDGE_FREE_MODE=1`): переносы не списывают токены, в интерфейсе нет кошелька, пополнения и промокодов, доход приносит рекламный блок (см. «Реклама»). Пополнение и промокоды на сервере отвечают `403`, админ-панель скрыта. Локальный режим и демо-цель не списывали токены и раньше.

Если захотите вернуть монетизацию токенами, уберите `TUNEBRIDGE_FREE_MODE` — включится прежняя экономика:

- **1 токен = 1 добавленный в плейлист трек.** Приветственный бонус — 50 токенов (`TUNEBRIDGE_TRIAL_TOKENS`).
- Пакеты (звёзды Telegram, курс для подписи в рублях — `TUNEBRIDGE_STARS_RATE`, по умолчанию 2 ₽ за звезду):

  | Пакет | Треки | Звёзды | ≈ рубли |
  | --- | --- | --- | --- |
  | Старт | 100 | 60 | 120 ₽ |
  | Про | 500 | 260 | 520 ₽ |
  | Максимум | 1000 | 480 | 960 ₽ |

- Оплата — Telegram Stars (`XTR`) без платёжного провайдера: `createInvoiceLink` → `WebApp.openInvoice` → `answerPreCheckoutQuery` → `successful_payment`.
- Идемпотентность: заказ хранится в `orders`, повторный `successful_payment` не начисляет токены второй раз; начисление в леджере `wallet_tx` защищено уникальным ключом `(kind, ref)`.
- В локальном режиме кнопка пополнения создаёт заказ со статусом «Тестовый» и сразу начисляет токены — удобно проверять интерфейс без Telegram.
- **Списание за перенос:** перед стартом с баланса резервируется по одному токену за каждый трек; после завершения возвращается всё, что реально не добавилось — не найдено, ошибка записи или отмена. В леджере остаются две операции с общим `ref`: `spend` и `refund`.
- Если токенов не хватает, перенос не начинается: сервер отвечает `402` с `code: insufficient_balance`, `needed` и `balance`, а интерфейс предлагает пополнить баланс или сократить плейлист.
- Демо-цель и локальный режим не списывают токены — их удобно использовать для проверки сопоставления без затрат.

### Вебхук и бот

Продакшн — вебхук по HTTPS:

```sh
curl "https://api.telegram.org/bot$TUNEBRIDGE_BOT_TOKEN/setWebhook" \
  -d "url=https://tunebridge.example.com/api/billing/telegram/webhook" \
  -d "secret_token=$TUNEBRIDGE_WEBHOOK_SECRET"
```

Сервер принимает обновления только с заголовком `X-Telegram-Bot-Api-Secret-Token`, равным `TUNEBRIDGE_WEBHOOK_SECRET`. Без секрета вебхук отвечает 503.

Для локальной проверки без домена: `TUNEBRIDGE_BOT_POLLING=1` — приложение само забирает обновления через `getUpdates` (offset хранится в базе). Вебхук и поллинг одновременно не включайте.

### Промокоды и админка

- Админ создаёт коды с количеством токенов, лимитом активаций, сроком и заметкой; код активируется один раз на пользователя, лимит и срок проверяются в транзакции.
- В админ-панели: пользователи, оборот токенов, оплаченные звёзды, проданные треки, ручное начисление по Telegram ID, список промокодов, последние заказы и возврат звёзд.
- Возврат (`refundStarPayment`) возможен только для оплаченного заказа из Telegram; токены списываются, если на балансе достаточно средств. Тестовые заказы не возвращаются.

### Ограничения хостинга

- Подключения музыкальных сервисов изолированы по аккаунтам и зашифрованы в базе — см. «Подключения сервисов в аккаунте». Ключ шифрования лежит в переменной окружения: его потеря или смена обнуляет подключения пользователей.
- Фоновые задачи живут в памяти процесса: при перезапуске сервера незавершённый перенос теряется. Запускайте один процесс на базу.
- Лимиты и юридическая обвязка (оферта, правила возврата, налоги) — на стороне владельца сервиса; перед публичным запуском проверьте требования Telegram к цифровым товарам и местное законодательство.

## Запуск в облаке (Oracle Always Free)

GitHub — это репозиторий и CI/CD, а не хостинг: сервер живёт на виртуальной машине. Бесплатный вариант — Oracle Cloud Always Free (ARM `VM.Standard.A1.Flex`, 2 OCPU / 12 ГБ, бессрочно; карта нужна только для верификации аккаунта).

В репозитории уже лежат `Dockerfile`, `docker-compose.yml` (приложение + Caddy с HTTPS), `.env.example`, скрипты `deploy/bootstrap-oracle.sh` (первичная настройка VM), `deploy/backup.sh`, `deploy/restore.sh`, `deploy/twa/build-twa.sh` (сборка Android) и workflows `ci.yml` / `deploy.yml`. Пошаговый runbook со всеми командами — в [DEPLOY.md](DEPLOY.md).

### 1. Виртуальная машина

1. Создайте аккаунт Oracle Cloud и выберите ближайший регион.
2. Compute → Instances → Create: shape **VM.Standard.A1.Flex** (2 OCPU, 12 ГБ), образ **Ubuntu 24.04**, приложите SSH-ключ.
3. В Networking → VCN → Security Lists откройте входящие TCP **80** и **443** (порт **22** — только со своего адреса).
4. На сервере установите Docker:

   ```sh
   sudo apt update && sudo apt install -y docker.io docker-compose-v2 git
   sudo usermod -aG docker "$USER"    # затем перелогиньтесь
   sudo ufw allow 80,443/tcp          # если ufw включён
   ```

### 2. DNS

A-запись домена → публичный IP инстанса. Caddy выпустит сертификат Let's Encrypt сам, как только DNS начнёт резолвиться.

### 3. Код и окружение

```sh
sudo mkdir -p /opt/tunebridge && sudo chown "$USER" /opt/tunebridge
git clone https://github.com/<you>/tunebridge.git /opt/tunebridge
cd /opt/tunebridge
cp .env.example .env
nano .env
```

Заполните домен, `TUNEBRIDGE_BOT_TOKEN`, `TUNEBRIDGE_BOT_USERNAME`, `TUNEBRIDGE_ADMIN_IDS`. Секреты сгенерируйте так:

```sh
python3 -c "import secrets; print(secrets.token_urlsafe(48))"   # TUNEBRIDGE_SECRET_KEY
python3 -c "import secrets; print(secrets.token_urlsafe(32))"   # TUNEBRIDGE_WEBHOOK_SECRET
```

`TUNEBRIDGE_FREE_MODE=1` уже стоит в примере. `TUNEBRIDGE_SECRET_KEY` нельзя менять после запуска: он шифрует подключения пользователей.

### 4. Запуск

```sh
docker compose up -d --build
docker compose ps          # оба контейнера healthy/running
docker compose logs -f caddy
```

Откройте `https://<домен>` — интерфейс должен загрузиться, в логах Caddy появится выданный сертификат.

### 5. Telegram

1. @BotFather → `/newbot`; токен и имя бота — в `.env`.
2. @BotFather → `/newapp` → выберите бота → URL `https://<домен>/`.
3. Вебхук (секрет — тот же, что `TUNEBRIDGE_WEBHOOK_SECRET`):

   ```sh
   curl "https://api.telegram.org/bot$TUNEBRIDGE_BOT_TOKEN/setWebhook" \
     -d "url=https://<домен>/api/billing/telegram/webhook" \
     -d "secret_token=$TUNEBRIDGE_WEBHOOK_SECRET" \
     -d 'allowed_updates=["message"]'
   ```

   В платном режиме добавьте `"pre_checkout_query"`.

4. После правки `.env` перезапустите приложение: `docker compose up -d`.

### 6. База и бэкапы

SQLite и зашифрованные подключения пользователей лежат в named volume `tunebridge_data`; пересборка контейнера их не удаляет. Резервная копия:

```sh

./deploy/backup.sh
```

Скрипт делает согласованный снимок базы (SQLite backup API), архивирует остальные файлы `data/` и удаляет копии старше 14 дней (`BACKUP_KEEP_DAYS`). Ежедневный cron:

```cron
17 3 * * * /opt/tunebridge/deploy/backup.sh >> /var/log/tunebridge-backup.log 2>&1
```

### Ограничения этого варианта

- Один процесс uvicorn: фоновые задачи живут в памяти. Для десятков одновременных переносов понадобится очередь (Redis/RQ или отдельный worker).
- SQLite справляется с небольшим сервисом; при росте — PostgreSQL (слой `app/db.py` изолирует запросы).
- Oracle может пересоздать бесплатный инстанс при простое; бэкапы и `git`-деплой позволяют поднять сервис заново за минуты.

## Реклама

Свой баннер вместо рекламной сети: без сторонних скриптов, CSP не ослабляется, блок работает и в Mini App, и в PWA. Задаётся переменными окружения:

| Переменная | Пример |
| --- | --- |
| `TUNEBRIDGE_AD_TITLE` | `Наушники со скидкой 20%` |
| `TUNEBRIDGE_AD_TEXT` | `Промокод TUNEBRIDGE — бесплатная доставка` |
| `TUNEBRIDGE_AD_URL` | `https://shop.example/promo` |
| `TUNEBRIDGE_AD_CTA` | `Купить` |
| `TUNEBRIDGE_AD_IMAGE` | `/static/img/ads/banner.png` |
| `TUNEBRIDGE_AD_LABEL` | `Реклама` |

- Блок показывается на главной и на экране результата, всегда с подписью «Реклама» / «Ad».
- Ссылка открывается в новой вкладке; `javascript:` и protocol-relative адреса картинок отбрасываются на сервере.
- Картинку положите в `static/img/ads/`, путь укажите от корня сайта, затем перезапустите контейнер.
- Если не заданы `TUNEBRIDGE_AD_TITLE` и `TUNEBRIDGE_AD_URL`, блок не показывается.
- AdSense в РФ не работает. Для старта проще прямые договорённости со своими баннерами; позже — Яндекс РСЯ/VK Реклама для сайта или Yandex Mobile Ads в нативном приложении (в PWA их SDK нет).
- Подпись «Реклама» обязательна: это требование закона о рекламе, не только вежливость.

## Приложения в сторах

**Android (TWA).** Обёртка открывает тот же сайт в полноэкранном Chrome. Готовый скрипт собирает приложение и генерирует assetlinks:

```sh
npm i -g @bubblewrap/cli
TWA_DOMAIN=<домен> bash deploy/twa/build-twa.sh
```

Скрипт рендерит `deploy/twa/twa-manifest.template.json`, создаёт `android.keystore`, собирает подписанные `.apk`/`.aab`, достаёт SHA-256 и печатает строки для `.env`. Подробности и публикация в Play — в [DEPLOY.md](DEPLOY.md#9-android-приложение-twa).

Вручную то же самое:

```sh
bubblewrap init --manifest https://<домен>/manifest.webmanifest
bubblewrap build
```

1. `bubblewrap init` спросит package id, имя и иконки; создаст `android.keystore`.
2. SHA-256 подписи: `keytool -list -v -keystore android.keystore -alias android`, строка `SHA256:`.
3. Пропишите `TUNEBRIDGE_TWA_PACKAGE` и `TUNEBRIDGE_TWA_SHA256` в `.env` (несколько отпечатков — через запятую) и перезапустите: приложение отдаст `/.well-known/assetlinks.json`, и адресная строка в TWA исчезнет.
4. Google Play: аккаунт разработчика — $25 разово, загрузка `.aab`, политика конфиденциальности, скриншоты.

**iOS.** Пока PWA: Safari → «Поделиться» → «На экран Домой». Для App Store нужен нативный каркас на WKWebView и аккаунт разработчика $99/год — это отдельный проект, сам сайт уже готов.

**Проверка PWA:** Chrome DevTools → Lighthouse → PWA. Manifest, иконки 192/512/maskable и service worker уже в проекте; установка и офлайн работают только по HTTPS.

## С телефона

1. Закройте TuneBridge, если он запущен.
2. Windows: двойной клик по `start-lan.bat`. macOS/Linux: `./start-lan.sh`.
3. В консоли появится адрес вида `http://192.168.1.85:8787` (компьютер по-прежнему открывает `127.0.0.1`).
4. Откройте этот адрес на телефоне или отсканируйте QR из боковой панели → **«С телефона»**.

Телефон и компьютер должны быть в одной Wi-Fi сети. Windows при первом запуске спросит про брандмауэр — разрешайте доступ **только для частных сетей**.

Интерфейс подстраивается под экран телефона: боковая панель сворачивается в меню, окна и таблицы перестраиваются. Через **«Добавить на главный экран»** появится иконка TuneBridge.

**Офлайн-режим и установка PWA** включаются только по HTTPS или на `localhost`: браузеры считают обычный `http://192.168…` небезопасным адресом. По Wi-Fi приложение работает полностью, но service worker и установка могут быть недоступны.

> В режиме Wi-Fi TuneBridge видят **все устройства в сети**, включая подключённые аккаунты. Включайте только в доверенной сети и выключайте после использования.

## Как работает сопоставление

- Названия нормализуются: регистр, диакритика, `ё → е`, апострофы, пунктуация, `feat.` и версии в скобках.
- Итоговый балл: **58 % название + 32 % исполнитель + 10 % длительность**.
- Балл ≥ **0.84** — автоматический перенос; **0.58–0.84** — на ручную проверку; ниже — «не найден».
- Версии (live, remix, instrumental и т.п.) штрафуются; remaster/deluxe/mono/stereo — мягко.
- Результаты поиска кешируются в `data/match_cache.json`, чтобы повторные переносы не дёргали API.

В спорных случаях можно заменить кандидата вручную, найти трек поиском или исключить строку из переноса.

## Приватность и данные

Сервер по умолчанию слушает только `127.0.0.1`. Никакой телеметрии и внешних запросов, кроме обращений к самим музыкальным сервисам и Bot API Telegram (только если вы подключили бота). В режиме Wi-Fi (`start-lan`) сервер слушает `0.0.0.0` и доступен всем в локальной сети. В режиме хостинга сервер доступен из интернета по HTTPS, а данные пользователей хранятся в `data/tunebridge.db`.

Всё состояние хранится в `data/` (папка в `.gitignore`):

| Файл | Что внутри |
| --- | --- |
| `tunebridge.db` | пользователи, сессии (хеши токенов), кошелёк, заказы, промокоды, переносы, зашифрованные подключения сервисов |
| `credentials.json` | токены и Client ID |
| `spotify_token.json` | OAuth-токен Spotify |
| `ytmusic_headers.json` | cookie и заголовки YouTube Music |
| `yandex_device.json` | состояние входа Яндекса |
| `telegram.json` | токен Telegram-бота и выбранный чат |
| `match_cache.json` | кеш сопоставлений |
| `exports/`, `tmp/` | временные файлы |

**Не публикуйте папку `data/`.** В локальном режиме токены и cookie лежат в открытом виде — это плата за запуск без шифрования. В хостинге подключения пользователей туда не пишутся: они лежат в базе зашифрованными. Отключение сервиса в интерфейсе удаляет соответствующую запись или файл. В базе нет паролей и `initData`: только подпись Telegram проверяется на входе, а от сессии хранится SHA-256.

## Ограничения

- Перенос **в** Яндекс Музыку, SoundCloud и Apple Music пока не поддерживается — эти сервисы работают как источники. Для них доступен экспорт файлов, а через M3U/CSV плейлист можно загрузить в Soundiiz и другие сервисы.
- Публичный импорт Spotify и Apple Music может отдавать не весь список треков (ограничение публичных страниц). Приложение предупреждает об этом; для полного доступа к своим плейлистам подключите аккаунт Spotify.
- Максимум **2000 треков** в плейлисте и **5 МБ** на импортируемый файл.
- Одновременно выполняется одна фоновая задача на пользователя (в локальном режиме — одна на всех); после перезапуска сервера незавершённые задачи теряются.
- Сопоставление эвристическое: редкие каверы, ремиксы и одноимённые треки лучше проверять вручную.
- YouTube Music и Яндекс Музыка используются через неофициальные API. Автоматизация действий в YouTube может нарушать его условия использования — используйте на свой риск.
- История в браузере не синхронизируется между устройствами; журнал переносов аккаунта хранится в базе и доступен после входа с любого устройства.
- Списание резервируется целиком до старта переноса: при обрыве питания или падении процесса возврат за недобавленные треки не выполнится — останется `spend` без `refund`. Для публичного сервиса это стоит закрыть периодической сверкой леджера.

```sh

.venv/bin/python -m unittest discover -s tests -t .            # macOS / Linux
```

Покрыты нормализация и версии треков, веса и пороги сопоставления, разбор ссылок Яндекса/Spotify/YouTube/SoundCloud/Apple Music, публичный импорт, разбор cookie и заголовков YouTube Music, выбор нужного аккаунта Google и запрет импорта из браузера с других устройств, чтение cookie из профилей браузеров, импорт M3U/CSV/JSON/TXT, экспорт ZIP, сохранение входа в Яндекс Музыку, Telegram-бот (токен, чаты, текст сообщения, отправка), определение адреса в локальной сети, проверка `initData`, сессии и CSRF, леджер кошелька, промокоды, предварительная проверка и идемпотентность оплаты, возвраты, изоляция задач по пользователям, списание токенов за перенос (резерв, отказ при нехватке, возврат за неудачные треки, бесплатные демо и локальный режим), бесплатный режим (без списаний, блокировка пополнений), рекламный блок и `assetlinks.json`, а также шифрование подключений: изоляция по пользователям, привязка записи к сервису, отказ при повреждённом шифротексте и отсутствии ключа.

## Диагностика

- **Порт занят** — закройте старый процесс или задайте `TUNEBRIDGE_PORT` и `TUNEBRIDGE_BASE_URL`.
- **Spotify: `redirect_uri: Invalid`** — Redirect URI в Dashboard должен совпадать посимвольно, включая порт и `/api/auth/spotify/callback`.
- **401 после сна** — токен истёк: подключите сервис заново.
- **YouTube Music: «вход не найден в браузере»** — откройте music.youtube.com, войдите в аккаунт в этом браузере и повторите; если профиль защищён паролем или браузер нестандартный, вставьте cookie вручную.
- **YouTube Music: ошибка авторизации** — cookie устарели: откройте music.youtube.com, войдите и скопируйте заголовок `cookie` заново.
- **YouTube Music: подключается не тот аккаунт** — отключите YouTube Music и подключите снова: если в браузере несколько аккаунтов Google, приложение попросит выбрать нужный. С телефона или из хостинга импорт из браузера недоступен — вставьте cookie своего аккаунта вручную.
- **Telegram: «Unauthorized»** — токен отозван или скопирован с ошибкой; создайте нового бота или перенесите токен заново. «Bad Request: chat not found» — откройте бота и нажмите Start, либо проверьте `@username` канала и права администратора.
- **Telegram: бот молчит в канале** — бот должен быть администратором канала; отправка в канал работает только по `@username`.
- **Плейлист Яндекса не находится** — он приватный; подключите аккаунт или используйте файл.
- **SoundCloud: «плейлист не найден»** — сет удалён или скрыт; нужна публичная ссылка вида `…/sets/…`.
- **Apple Music: треков меньше, чем в плейлисте** — публичная страница отдаёт не весь список; это ожидаемое ограничение.
- **Телефон не открывает адрес** — проверьте, что оба устройства в одной Wi-Fi сети и в брандмауэре Windows разрешён доступ для частных сетей. Гостевые и корпоративные сети часто изолируют устройства друг от друга.
- **Нет кнопки «Установить приложение»** — браузер требует HTTPS. По `http://192.168…` пользуйтесь приложением во вкладке или добавьте ярлык через меню браузера.
- **Хостинг: «Нужен вход через Telegram»** — откройте приложение как Mini App внутри Telegram; вход по ссылке в обычном браузере не подтверждается. Проверьте, что `TUNEBRIDGE_BOT_TOKEN` и адрес Mini App в BotFather указывают на один бот.
- **Вебхук отвечает 403** — `secret_token` в `setWebhook` не совпадает с `TUNEBRIDGE_WEBHOOK_SECRET`; перевызовите `setWebhook`.
- **Вебхук отвечает 503** — не задан `TUNEBRIDGE_WEBHOOK_SECRET`. Для проверки без домена включите `TUNEBRIDGE_BOT_POLLING=1`.
- **Оплата прошла, токены не пришли** — Telegram не доставил `successful_payment`: проверьте `getWebhookInfo` (последняя ошибка доставки) или логи сервера. Повторная доставка безопасна — заказ идемпотентен.
- **«Промокод не найден» / «Промокод истёк» / «уже использован максимальное число раз»** — код отключён, истёк или исчерпал активации; один и тот же код нельзя активировать дважды с одного аккаунта.
- **«Недостаточно треков на балансе»** — на счету меньше, чем в выбранном плейлисте. Пополните баланс или сократите список: списываются только добавленные треки, за неудачные совпадения возврат придёт автоматически.
- **Хостинг: подключения пропали после перезапуска** — изменился `TUNEBRIDGE_SECRET_KEY` (включая смену токена бота, если отдельный ключ не задан). Верните прежний ключ или подключите сервисы заново.
- **Хостинг: нет кнопки «Найти чаты»** — так и задумано: очередь обновлений бота общая для всех пользователей. Введите @username канала или оставьте поле пустым, чтобы отправить в личный чат с ботом.
